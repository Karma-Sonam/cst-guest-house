# Backend foundation

Spring Boot starter generated by the official Spring Initializr, using Java 21 and its supplied Maven wrapper. The generated parent version is pinned in backend/pom.xml. No system-wide Maven installation is required.

## Files

- backend/src/main/java/bt/edu/cst/guesthouse: config, controller, dto, entity, exception, repository and service packages.
- backend/src/main/resources/db/migration/V1__identity_and_inventory.sql: PostgreSQL users, revocable sessions, initial ten rooms and two facilities.
- compose.yaml: local PostgreSQL with a persistent volume and loopback-only database port.

## Run in PowerShell

Start Docker Desktop in Linux container mode first. The project database uses localhost:55432 to avoid conflicting with other PostgreSQL installations. From D:\GuestHouse:

```powershell
Copy-Item .env.example .env
# Edit .env and replace passwords and JWT_SECRET before continuing.
docker compose up -d postgres
$env:JAVA_HOME = 'C:\Program Files\Java\jdk-21'
$env:Path = "$env:JAVA_HOME\bin;$env:Path"
# Optional, for first admin creation only:
$env:ADMIN_EMAIL = 'your-admin-email'
$env:ADMIN_PASSWORD = 'your-strong-admin-password'
Set-Location D:\GuestHouse\backend
.\mvnw.cmd test
.\mvnw.cmd package
.\run-local.ps1
```

Spring Boot does not automatically read the root .env file. The run-local.ps1 helper explicitly loads it into the current process before launching the packaged backend; Compose reads it for PostgreSQL. Remove bootstrap credentials after first administrator creation. Existing administrator passwords are never reset on startup. Use a second PowerShell terminal to run `D:\GuestHouse\backend\test-api.ps1`; expected output is PASS for each check. This script creates a uniquely named test user in the local database and requires registration to be enabled.

## Authentication API

POST /api/auth/register accepts fullName, email, password, optional phone. Passwords require 12 characters and at most 72 UTF-8 bytes. Returns a safe USER DTO and HTTP 201. Registration can be disabled.

POST /api/auth/login accepts email and password. Returns token, expiresIn and user. Send subsequent requests with Authorization: Bearer TOKEN. GET /api/auth/me returns the authenticated user. POST /api/auth/logout returns 204 and revokes that token's session. Disabled users fail session validation. User role is read from the database rather than trusted from client input.

GET /actuator/health is public and does not disclose database details. /api/admin/** requires ADMIN. Future admin controllers are not implemented yet.

Use tokens in memory in the later frontend, not persistent browser localStorage. This API uses bearer headers and no authentication cookies; any future cookie authentication requires revisiting CSRF protection.
